# Phase 6 — 검증·배포 Plan

> 마스터플랜: `docs/superpowers/plans/2026.07.26_전면개편_마스터플랜.md`. 이 Phase는 검증 중심이라 컨트롤러 주도(결정적 Playwright 스크립트 — Phase 4·5에서 확립된 방식)로 실행하며, SDD 서브에이전트 구현 루프는 결함 수정 시에만 사용한다.

**Goal:** 전 기능 회귀 + 전수 체크리스트 대조 + 통합 워크플로 E2E + 크로스브라우저 + Lighthouse → **사용자 승인 후** main 머지 → 프로덕션 검증 + 구버전 실데이터 마이그레이션 확인.

**완료 기준(마스터플랜):** 구버전 저장 프로젝트가 새 앱에서 열림 + 프로덕션 URL 정상.

## 핵심 인식

- **구버전 실데이터는 프로덕션 origin(renewable-proposal.vercel.app)의 localStorage에 있음** — Preview 도메인에서는 접근 불가. 따라서 실데이터 확인은 **머지 후** 프로덕션에서 사용자가 직접 수행(가져오기 버튼). 머지 전에는 시뮬레이션 데이터로 검증(Phase 5에서 완료, 이번에 통합 시나리오로 재확인).
- **main 머지는 프로덕션 전환**(구앱 → 새 앱). 구앱은 `legacy/`로 레포에 보존되어 있고 localStorage 원본(projects_v2)은 삭제하지 않으므로 롤백 가능(revert 배포). 머지 직전 사용자 확인 필수.
- Lighthouse는 인증 없는 프로덕션 URL에서 실행(머지 후). 머지 전에는 생략하고 근거 기록.
- 지도 타일(NCP Web Dynamic Map)은 사용자 콘솔 작업 대기 — 폴백 동작은 검증됨. 미완이어도 머지 차단 사유 아님(주소검색·드롭다운 경로 정상). 프로덕션 도메인(`renewable-proposal.vercel.app`)의 NCP 웹 서비스 URL 등록도 같은 사용자 액션에 포함.

## Tasks

### Task 1: 회귀 + 전수 체크리스트 대조
- `npm test`(44) + verify 스냅샷 2종 IDENTICAL
- 마스터플랜 "기존 기능 전수 체크리스트"(11항목) ↔ 구현·검증 증거 대조표 작성 → 이 계획 문서 하단에 기록, 커밋

### Task 2: 통합 워크플로 E2E (Preview, msedge)
단일 연속 시나리오(신규 사용자 여정): 대시보드에서 프로젝트 생성(UI) → ① 사업정보 폼 입력 + 주소검색(테헤란로 152 — 서울특별시 자동) + 세대수 → ② 검토 계산(5,492,250·판정) → ③ 최적화(탐색·카드) → AI 추천(⭐) → ④ 검토의견 생성 → 보고서 미리보기(5,492,250) → 새로고침 후 전 단계 데이터 유지. 콘솔 에러 수집.

### Task 3: 크로스브라우저
Task 2 시나리오를 chrome 채널로 재실행(Playwright channel: "chrome" — Chrome 미설치 시 chromium/기록). Firefox·Safari는 환경 부재 — 기록.

### Task 4: 머지 승인 (사용자)
검증 결과 요약 제시 → AskUserQuestion으로 main 머지 승인.

### Task 5: main 머지 + 프로덕션 검증
`git checkout main && git merge revamp/next`(ff 또는 merge commit) → push → 프로덕션 배포 READY → 프로덕션 스모크(대시보드·engine-check·/api/geocode) → Lighthouse(프로덕션 URL) → 사용자 실데이터 확인 가이드 안내(구버전 가져오기 버튼).

### 롤백 절차(비상): main에서 `git revert -m 1 <merge commit>` 푸시 → 구앱 재배포. localStorage 원본 무손실.
