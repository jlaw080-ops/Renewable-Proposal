# 신재생에너지 의무설치비율 검토 웹앱 — 전면 개편 설계문서

> 작성 2026-07-26 | 상태: 사용자 검토 대기
> 목표: 상용 SaaS 수준의 페이지 구성·디자인으로 전면 개편 + 신기능 3종 추가

## 1. 목표와 원칙

- **UI는 100% 신규**: Next.js(App Router) 기반으로 페이지 구성·디자인 전면 재구축
- **계산 엔진은 무수정 재사용**: `engine/`, `optimize/`, `data/`, `vendor/`(LP솔버)는 코드 수정 없이 그대로 사용 — 포팅 리스크 제로
- **계산 결과 동일성 증명**: 개편 전 `verify/` 스크립트로 기준값 스냅샷 확보 → 개편 후 100% 일치 확인
- **기존 기능 전수 이관**: 사업정보 입력, 시나리오(ALT), Output1/2 계산, 최적화, 보고서(PDF/Word/HTML), 설정 편집, 프로젝트 저장/불러오기 — 누락 없음

## 2. 아키텍처

### 2.1 기술 스택

| 구분 | 선택 | 비고 |
|------|------|------|
| 프레임워크 | Next.js (App Router) | Vercel 배포 (기존 계정·프로젝트 유지) |
| 계산 엔진 | 기존 Vanilla JS 무수정 재사용 | `<Script>` 로드 → `window.LIB_*`·전역 IIFE 유지 |
| 엔진 접근 | 얇은 어댑터 훅 (`useEngine` 등) | React는 window 전역을 어댑터를 통해서만 접근 |
| 지도 | 네이버 지도 JS SDK | NCP 키 기존 보유, `api/geocode.js` 프록시와 계정 통일 |
| AI | Gemini (기존 `api/recommend.js` 프록시 재사용) | 스트리밍 유지 |
| 저장 | localStorage (기존 방식 유지) | 구버전 프로젝트 데이터 마이그레이션 포함 |

### 2.2 레포 구성

- 기존 루트의 앱 코드(index.html, style.css 등)는 `legacy/`로 이동해 보존
- 엔진 모듈(`engine/`, `optimize/`, `data/`, `vendor/`, `settings/`의 스토어 로직)은 새 앱의 정적 자원으로 로드
- 서버리스 함수 `api/`는 Next.js API 라우트(또는 기존 형태 유지)로 통합

## 3. 페이지 구성 (상용 SaaS 형태)

```
/                  대시보드 — 프로젝트 목록·새 프로젝트 생성
/project/[id]      프로젝트 워크스페이스 (좌측 단계 네비게이션)
  ├ ① 사업정보     사업형태·연도·용도별 연면적 + 지도 기반 위치 선택(신규)
  ├ ② 검토 계산    Output1(예상에너지사용량) → Output2(설치비율·의무비율 판정)
  ├ ③ 최적화·AI    설비조합 최적화 + AI 추천 통합(신규)
  └ ④ 보고서       미리보기·다운로드(PDF/Word/HTML)·메모
설정 모달           라이브러리·가중치 편집 (localStorage 오버라이드, 기존 로직 이관)
```

## 4. 신기능 상세

### 4.1 지도 기반 위치 조회

**입력 경로 3종 (동급, 모두 유지)**
1. 드롭다운 직접 선택 (현행)
2. 주소 검색 — 기존 `api/geocode.js`(네이버 Geocoding 프록시) 재사용
3. 지도 클릭 — 신규 `api/reverse-geocode.js` 프록시 추가 (네이버 Reverse Geocoding)

**동작**: 어느 경로든 기존 `시도매핑`(강원 영동/영서 구분 포함) 로직을 통과시켜 의무비율 지역을 자동 확정한다.
예: "서울특별시 강서구 곰달래로 123" 검색 → 지도 마커 표시 → 지역 = 서울특별시 → 해당 의무비율 자동 호출.

### 4.2 토지정보 조회 (지도 조회 부가기능)

**표시 항목**: 대지면적, 건폐율, 용적률, 건축면적, 연면적

**데이터 흐름**:
```
주소 확정 → 도로명주소 API(juso.go.kr)로 법정동코드·지번 획득
         → 국토교통부 건축물대장 표제부 API(data.go.kr) 조회
         → 신규 프록시 api/landinfo.js 경유 → 화면 카드 표시
```

**설계 결정**:
- 조회된 **연면적은 사업정보의 총 연면적 필드에 자동 채움** — 단, 수정 가능 필드 (신축 검토 시 계획 연면적으로 덮어쓰기). 용도별 연면적 배분은 기존대로 사용자 입력
- 건축물대장은 기존 건물 기준이므로 화면에 "현황 건축물 기준" 라벨 명시 (건폐율·용적률은 법정 한도가 아닌 실적치)
- 나대지 등 조회 결과 없음 → "조회 결과 없음" 표시 후 수기 입력 (에러 아님)
- **선행 조건**: 공공데이터포털(data.go.kr)·도로명주소(juso.go.kr) 무료 API 키 발급 — 사용자 액션 필요, Vercel 환경변수로 등록

### 4.3 최적화 + AI 추천 통합

현행 "알고리즘 vs AI 비교" 구조(숨김 탭)를 폐기하고 **단방향 파이프라인**으로 재구성:

```
최적화 실행 → 상위 조합 카드(챔피언 태그) 표시
→ [AI 추천 받기] 버튼 클릭 시:
    최적화 결과(상위 N 조합 + ctx)를 Gemini에 전달
    → 추천 조합 선정 + 근거를 스트리밍 표시
    → 해당 카드에 ⭐AI 추천 배지 + 근거 패널
```

- **버튼 트리거 방식** (자동 호출 아님 — 비용·대기시간 제어)
- 기존 재사용: `api/recommend.js`(Gemini 스트리밍 프록시), `recommendEngine.js`의 후보 수집 로직
- 프롬프트는 "순위 비교"에서 "추천 + 선정 근거"로 재작성 (`recommendPrompt.js` 수정)
- AI 별도 탭 없음 — 최적화 결과 화면 내 통합

## 5. 디자인 방향

- 라이트 SaaS 테마 유지·발전 (직전 ENERBUILD 레퍼런스 개편의 연장선)
- 디자인 토큰(색·타이포·간격) 체계화, 공통 컴포넌트(버튼·카드·입력·테이블·모달) 정립
- 반응형: 데스크톱 우선, 태블릿 대응
- 구체적 스타일 가이드는 Phase 1에서 frontend-design 절차로 확정

## 6. 워크플로우 (6 Phase)

| Phase | 작업 | 완료 기준 |
|-------|------|----------|
| **0. 기반** | Next.js 스캐폴드, `legacy/` 보존 재구성, Vercel 연결, verify 스냅샷 확보 | 배포 동작 + 계산 기준값 스냅샷 |
| **1. 셸·디자인 시스템** | 토큰·공통 컴포넌트·대시보드/워크스페이스 레이아웃·단계 네비 | 전 화면 골격 + 반응형 |
| **2. 사업정보+지도** | 입력 폼 이식, 네이버 지도(검색·클릭·역지오코딩), 토지정보 조회 | 3경로 지역 확정 일치 + 토지정보 카드·연면적 자동 채움 |
| **3. 검토 계산** | Output1·Output2 화면, 시나리오 ALT 관리 | verify 스냅샷과 100% 일치 |
| **4. 최적화+AI** | 최적화 UI 이식, AI 추천 버튼·스트리밍·배지 | 최적화 결과 일치 + AI 추천 표시 |
| **5. 보고서·설정·저장** | 리포트 3종 다운로드, 설정 모달, 프로젝트 저장/불러오기·마이그레이션 | 기존 기능 전부 동작 |
| **6. 검증·배포** | 회귀 확인, 반응형·크로스브라우저, 프로덕션 배포 | 구버전 저장 프로젝트가 새 앱에서 열림 |

각 Phase 종료 시 사용자 체크포인트.

## 7. 리스크와 대응

| 리스크 | 대응 |
|--------|------|
| 엔진의 window 전역 의존이 Next.js SSR과 충돌 | 엔진 접근 컴포넌트는 전부 클라이언트 컴포넌트 + `<Script>` 로드 완료 후 실행 보장 (어댑터에서 로드 상태 관리) |
| 공공 API 키 발급 지연 | Phase 2 착수 전 사용자에게 발급 안내, 미발급 시 토지정보만 후순위로 미루고 지도 기능 먼저 진행 |
| 건축물대장 조회 불가 지번(나대지 등) | "조회 결과 없음" 정상 처리 + 수기 입력 경로 유지 |
| localStorage 구버전 데이터 호환 | Phase 5에서 마이그레이션 함수 작성, Phase 6에서 실데이터 확인 |
| jsPDF/html-docx-js 등 CDN 라이브러리의 번들 통합 | npm 패키지 전환 우선, 불가 시 기존 CDN 로드 방식 유지 |

## 8. 범위 제외 (명시)

- 서버 DB·로그인 등 멀티유저 기능 (localStorage 유지)
- 계산 엔진 로직 변경 (HANDOFF_설비최적화.md의 P3/P6 잔여 과제는 본 개편 범위 아님)
- 모바일 전용 최적화 (태블릿까지만)
