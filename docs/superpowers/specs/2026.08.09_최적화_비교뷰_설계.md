# 최적화 조합 비교 뷰 설계 (UX ④)

- **무엇을**: 최적화 조합 목록에 표(비교) 뷰를 추가하고, 정렬·필터를 붙인다. 기존 카드 뷰는 상세용으로 유지하고 토글로 전환한다.
- **왜**: 조합 20개가 점수순 카드로만 나열되어, 숫자 비교(초기비용·연간순익·의무비율)와 후보 좁히기가 눈으로 훑는 수작업이다.
- **결론**: 비교는 표로, 검토는 카드로. 행 클릭으로 해당 카드 상세로 이동한다.

작성일: 2026-08-09 · 승인: 사용자 (선택지 A "뷰 전환 + 정렬/필터")

## 1. 컨트롤 바 (조합 순위 카드 헤더 아래)

- **뷰 토글**: `표` / `카드` — 기본값 **표**(비교가 이 화면의 주 목적). 선택은 프로젝트에 저장하지 않음(세션 내 상태)
- **정렬**: 종합점수(기본, 내림) · 초기비용 · 연간순익 · 의무비율 · 면적이용률. 같은 항목 재선택 시 방향 토글(▼/▲)
- **필터**(체크박스, AND 결합):
  - `의무비율 충족만` — `targets.법적규제.의무설치비율_충족 === true`
  - **에너지원별** — 결과에 실제 등장하는 에너지원만 동적 생성. 대분류는 `items[].설비.형식`(예: "태양광"·"지열"·"연료전지" — `window.LIB_설비최적화` 항목의 `형식` 필드). 체크한 에너지원을 **포함**하는 조합만(체크 항목 간 OR, 다른 필터와는 AND)
- 필터·정렬은 **표시 목록(상위 20)에만 적용**하지 않고 `ranked` 전체에 적용한 뒤 상위 20을 취한다 — 필터를 걸면 그 조건의 상위 20이 나와야 의미가 있다
- 결과 0건이면 "조건에 맞는 조합이 없습니다 — 필터를 완화하세요" 안내 + 초기화 버튼

## 2. 표 뷰 (`components/optimize/ComboTable.jsx`)

| 열 | 내용 | 정렬 |
|---|---|---|
| # | `rank` (원래 순위 — 정렬해도 조합의 고유 번호로 유지) | — |
| 설비 구성 | `items[]`의 `설비.세부형식 · 용량kW` 요약(2개 초과 시 `외 N개`) | — |
| 점수 | `Math.round(score*100)` | ✓ |
| 초기비용 | `억(targets.초기비용)` | ✓ |
| 연간순익 | `만(targets.운영순익)` | ✓ |
| 의무비율 | `%` + 충족 기호(✓/✕) | ✓ |
| 면적이용 | `면적이용률 %` | ✓ |
| 배지 | ⭐AI 최선 · ★챔피언 태그 유무 | — |

- 기존 `Table` 공통 컴포넌트 재사용(가로 스크롤·정렬 헤더는 이 화면 전용 CSS로 보강)
- 행 클릭 → 카드 뷰로 전환 + 해당 조합 카드로 스크롤·포커스(`#combo-{rank}`)
- 접근성: 정렬 헤더는 `<button>` + `aria-sort`, 행은 `<tr>`에 클릭·`Enter/Space` 키 핸들러 대신 **첫 열에 링크 성격의 버튼**을 두어 키보드 도달 가능하게 한다(전체 행 클릭은 마우스 편의 기능)

## 3. 카드 뷰

- 기존 `ComboCard` 그리드 유지. 각 카드 래퍼에 `id="combo-{rank}"`와 `scroll-margin-top` 부여
- 정렬·필터는 카드 뷰에도 동일 적용(같은 목록을 공유)

## 4. 순수 로직 (`lib/comboView.js`, TDD)

- `SORT_KEYS` — `{key, label, get(combo), dir}` 정의 배열(기본 방향 포함: 점수·연간순익·의무비율·면적이용은 내림, 초기비용은 오름)
- `sortCombos(list, key, dir)` → 새 배열(불변). 값이 null/undefined면 항상 뒤로
- `energySources(list)` → 결과에 등장하는 에너지원 대분류 목록(중복 제거·등장 순서)
- `filterCombos(list, {의무충족만, sources})` → 새 배열. `sources`가 비면 에너지원 조건 무시
- `comboSummary(combo)` → 설비 구성 요약 문자열
