# 대시보드 정보화 + 단계 유도 설계

- **무엇을**: 대시보드 프로젝트 카드에 진행 단계·판정 요약을 표시하고, 워크스페이스 4개 화면 하단에 "다음 단계" 유도 바를 추가한다.
- **왜**: Technical Teal 개편 후에도 사용 흐름이 바뀌지 않아 체감이 약함 — 카드가 이름·날짜뿐이라 열어봐야 상태를 알고, 단계 이동을 나브 클릭에 의존한다.
- **결론**: UX 개선 1차(①+②) — 화면 내부 배치(③검토계산 2열·④최적화 비교뷰·⑤온보딩)는 범위 밖.

작성일: 2026-08-09 · 승인: 사용자 (설계 승인, 서브에이전트 실행 선택)

## 1. 결정 사항

| 결정 | 내용 | 근거 |
|---|---|---|
| 판정 계산 위치 | 저장하지 않고 **대시보드에서 엔진 실시간 계산** | Phase 3 "파생값 미저장" 데이터 계약 유지·항상 최신. 엔진은 순수 JS(프로젝트당 ms) |
| 대표 ALT | **설치비율 최대** ALT (동률이면 앞 순서) | 시나리오 여러 개일 때 한 칸 요약 기준 |
| CTA 활성 정책 | **항상 활성** (입력 부족해도 이동 가능) | 다음 화면이 이미 부족분을 안내함. 셸이 자식 실시간 입력을 모르는 구조라 조건부는 staleness 유발 |
| CTA 위치 | `WorkspaceShell` 하단 공통 바 1곳 | 4개 페이지 개별 수정 없음(DRY) |
| 카드 딥링크 | 카드 클릭 = **첫 미완료 단계**로 이동 | "이어서 하기" 동선 단축 |

## 2. 신규 모듈 — `lib/projectSummary.js` (순수 함수, TDD)

- `pickRepresentative(output2)` → `{id, 비율, 의무비율, 만족여부} | null` — 비율 최대 ALT, 빈 배열이면 null
- `nextSegment(statuses)` → `"info"|"calc"|"optimize"|"report"` — info→calc→optimize→report 순서에서 첫 `"done"` 아닌 단계, 전부 done이면 `"report"`
- `VERDICT_UI` — `{Yes:{tone:"pass",label:"만족",sym:"✓"}, No:{tone:"fail",label:"불만족",sym:"✕"}, 해당없음:{tone:"na",label:"해당없음",sym:"–"}}` (Output2Panel과 동일 문법)

## 3. ① 대시보드 카드 (`app/page.js` + `app/dashboard.css`)

- `useEngineReady()` + 프로젝트별 `runCalculation` (canCalculate ok·시나리오 존재·규모등급 판정 가능한 프로젝트만, try/catch로 실패 시 판정만 생략)
- 카드 구성: 프로젝트명 / **4점 단계 인디케이터**(`stepStatuses(p, null)` 재사용, done=틸 채움 `--accent-graphic`, todo=외곽선) + 수정일 / **판정 요약 줄**(Badge pass·fail·na + `설치 x.x% / 의무 y%` mono) / "이어서: {단계} →" 문구
- 카드 클릭 딥링크 = `/project/{id}/{nextSegment}`
- 접근성: 인디케이터에 `aria-label="4단계 중 N단계 완료"`, 판정 배지는 기호 병행(기존 규칙)

## 4. ② 단계 유도 바 (`WorkspaceShell.jsx` + `workspace.css`)

- `ws__content` 안, `{children}` 아래 공통 렌더:
  - 다음 단계 있음: 좌측 힌트 "다음 단계 — {desc}" + 우측 `다음: {label} →` (btn--primary 스타일 Link)
  - 마지막(보고서): "검토 절차의 마지막 단계입니다" + `완료 — 대시보드로` (btn--ghost Link)
