# 사업정보 입력 진행 상황판 설계 (UX ⑤)

- **무엇을**: ① 사업정보 화면 최상단에 "계산에 필수인 항목" 체크리스트를 두어, 무엇이 채워졌고 무엇이 남았는지 항상 보이게 한다.
- **왜**: 새 프로젝트를 만들면 빈 폼만 나와서 어디서 시작해야 하는지·무엇이 필수인지 단서가 없다. 부족한 항목은 ② 검토 계산에 가서야 알게 된다.
- **결론**: 필수 항목의 충족 여부를 입력 화면에서 즉시 보여준다. 추가 화면·모달·샘플 데이터는 만들지 않는다.

작성일: 2026-08-09 · 승인: 사용자 (선택지 A "입력 진행 상황판")

## 1. 표시 내용

- 위치: `① 사업정보` Card **위**의 독립 Card(`inner`) — 폼보다 먼저 읽히도록
- 헤더: `계산에 필수인 항목` + `N/4 입력됨` (mono)
- 항목 4개(계산 필수 조건과 동일): 사업형태 · 사업연도 · 대지위치 · 용도별 연면적
  - 충족: `✓` + 기본 텍스트 색
  - 미충족: `○` + 보조 텍스트 색
  - 색 단독 의존 금지 — 기호가 항상 함께 (기존 판정 표기 규칙과 동일)
- 전부 충족 시: 항목 목록 대신 한 줄로 축약 — `✓ 필수 항목을 모두 입력했습니다 — ② 검토 계산에서 결과를 확인하세요.` (완료 후에도 상황판이 자리를 많이 차지하지 않도록)
- 규모등급 보조 안내: 용도에 공동주택이 있고 세대수 미선택이면 `공동주택 세대 수를 선택하면 규모등급이 판정됩니다` 한 줄 추가(계산 실행에는 필수지만 `canCalculate` 대상은 아니므로 별도 표기)

## 2. 판정 근거

- **`canCalculate(input1)`(lib/calcModel.js) 재사용** — `{ok, missing}`의 `missing` 배열에 담기는 라벨이 곧 미충족 항목이다. 새 판정 로직을 만들지 않는다(중복 정의 금지)
- `missing`의 라벨 문자열: `"사업형태"`, `"사업연도"`, `"대지위치"`, `"용도별 연면적"`
- 진행 개수 = `4 - missing.length`
- 세대수 안내는 `calc규모등급(용도별연면적목록)`이 빈 문자열일 때만 표시

## 3. 구현 방식

- 신규 컴포넌트 `components/info/RequiredChecklist.jsx` + CSS. props: `{ input1 }`
- `app/project/[id]/info/page.js`는 이 컴포넌트를 첫 카드로 렌더하는 한 줄만 추가 — 기존 폼·핸들러·저장 로직 무변경
- 순수 판정은 기존 모듈을 쓰므로 신규 순수 로직·테스트는 없다. 대신 **`canCalculate`의 라벨 문자열이 체크리스트 항목과 일치함을 보장하는 테스트**를 추가한다(라벨이 바뀌면 상황판이 조용히 깨지는 것을 방지)
