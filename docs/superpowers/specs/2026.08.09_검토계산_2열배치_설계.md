# 검토 계산 화면 2열 배치 + 판정 고정 바 설계 (UX ③)

- **무엇을**: 검토 계산 화면을 넓은 화면(≥1280px)에서 좌(입력)·우(결과) 2열로 나누고, 그 미만에서는 판정 요약을 상단에 고정한다.
- **왜**: 시나리오를 수정하고 결과를 확인하려면 세로로 멀리 스크롤을 왕복해야 한다 — 이 앱에서 가장 반복되는 조작이다.
- **결론**: 넓은 화면은 왕복 자체를 제거, 좁은 화면은 판정만 항상 보이게 한다. 계산 로직·데이터 계약은 손대지 않는다.

작성일: 2026-08-09 · 승인: 사용자 (선택지 A "2열 + 좁은화면 sticky")

## 1. 배치 규칙

| 뷰포트 | 배치 |
|---|---|
| **≥1280px** | 2열 그리드 — 좌: 시나리오(ALT) 편집 / 우: 결과(판정 밴드 → Output1 표 → 설비별 표). 우측 열은 `position: sticky; top: 0`으로 스크롤 시 따라옴 |
| **<1280px** | 기존 1열 순서 유지(Output1 → 시나리오 → Output2) + **판정 고정 바**를 콘텐츠 상단에 `sticky` |

- 2열에서 상태 안내 카드(사업정보 부족·엔진 오류)는 **전폭**으로 두 열 위에 표시한다.
- 좌우 열 각각 독립 스크롤을 만들지 않는다(중첩 스크롤 금지) — 페이지 스크롤 하나만 유지하고 우측 열만 sticky.

## 2. 판정 고정 바 (신규 컴포넌트 `components/calc/VerdictSticky.jsx`)

- 대표 ALT 1건 요약: `{ALT-id} · {비율}% / 의무 {의무비율}% · {배지}` — 대표 선택은 **기존 `pickRepresentative`(lib/projectSummary.js) 재사용**
- ALT가 2개 이상이면 배지 뒤에 `외 N개` 표기
- 결과가 없으면(입력 부족·계산 전) 렌더하지 않음
- `<1280px`에서만 표시(2열에서는 우측 열 상단 판정 밴드가 그 역할)
- 스타일: 판정 톤별 좌측 4px 보더 + 틴트 배경 — 기존 `.verdict` 토큰 재사용, 높이는 1줄

## 3. 구현 방식

- `app/project/[id]/calc/page.js`: 마크업을 `calc__notices`(전폭) / `calc__col-input` / `calc__col-result` 3영역으로 재배치. **계산 훅·상태·엔진 호출은 무변경**
- `app/project/[id]/calc/calc.css`: 기본 1열, `@media (min-width: 1280px)`에서 `grid-template-columns: minmax(0, 1fr) minmax(0, 1.1fr)` + 우측 `position: sticky; top: var(--sp-4); align-self: start; max-height: calc(100vh - var(--sp-8)); overflow-y: auto`
  - 우측 열 내부 스크롤은 sticky 열이 뷰포트보다 길 때만 동작하며, 페이지 스크롤과 충돌하지 않도록 `overscroll-behavior: contain` 부여
- 판정 고정 바는 `@media (max-width: 1279px)`에서만 `display: flex`, 그 이상은 `display: none`
